02

Is yours covered?

Threema

Everything in the backup comes out, including the media Threema keeps inside its own database, where a file-level tool finds nothing at all.

WhatsApp

Everything in the backup comes out. For some entries only WhatsApp's own small preview was ever saved — those are marked as such instead of being passed off as originals.

Signal — no

Nothing this tool can change: Signal keeps its data out of the iOS backup entirely. It is detected, and then you are told exactly that. The way across is Signal's own device transfer.

03

What you need

A Mac

Developed and verified on macOS. Windows is implemented but has never been run against a real backup — that is written down, not glossed over.

A local backup

Made with the Finder, on this machine. Encrypted backups are the normal case and it copes with them; the password is only ever typed in, never passed as an argument.

A terminal

To be blunt: this is a command-line tool and Python 3.12. If typing three commands into a terminal is not for you, this is not for you either.

Some disk space

Roughly what the messenger's own data takes up. The backup is never copied, and the chat folders are free — they point at the same files.

04

How to start

1

Look before you touch

Reports which messengers are in the backup and what is inside. Writes nothing at all.

msgx analyze --backup ~/…/Backup/<device>
2

Rehearse, then run

With --dry-run it shows what would happen and writes nothing. The same plan drives the real run, so the rehearsal cannot behave differently from the real thing.

msgx extract --backup … --output ~/export/threema
3

Look through it

Builds the page. You open it with a double-click. Selecting happens there, copying happens with msgx collect — a page opened from disk may display your files but not read them.

msgx ui --output ~/export

Installation

Three lines, and one trap worth knowing about.

git clone https://github.com/abnun/msgbackup-extractor.git python3 -m venv ~/.venvs/msgx ~/.venvs/msgx/bin/pip install -e .

The terminal needs Full Disk Access, and it must be restarted afterwards, or it cannot read the backup at all.

Do not put the virtual environment inside iCloud Drive. iCloud hides the .pth files, Python then skips them silently, and the install looks like it worked when it did not. The handbook shows how to check.

05

Why you can trust it

Short version: because you do not have to take my word for any of it. Each of these has a test in the source that fails if it stops being true, and you can run them yourself with python -m pytest.

The backup is only read

A fingerprint of every file is taken before and after a full run and compared. Counter-tests prove the fingerprint would notice a change.

Nothing goes anywhere

No part of the source imports a network module. Checked statically, and again with networking switched off entirely.

Nothing arrives broken

Every written file's SHA-256 is read back and compared against the source. Only the comparison counts, never the claim.

One condition

This is for your own backup. It holds messages other people sent you, and private use is one thing while passing them on is another. Running it against someone else's backup can be a criminal offence. Don't.
